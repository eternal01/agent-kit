# 架构决策记录

## 边界
ADR 记录一个影响较大、难以逆转或需要长期解释的决策。探索架构使用 `system-architecture`，比较具体技术使用 `technology-selection`。

## 确认门禁
用户明确要求创建或修改 ADR，即视为对所述范围的授权。决策未达成、影响难以逆转或写入范围发生变化时，先列出待决项和拟修改文件，确认后再写入。

## 流程
1. 检查仓库已有 ADR 目录、编号、模板和状态约定，优先遵循现状。
2. 每份 ADR 只记录一个决策；写明背景问题、约束和决策驱动因素。
3. 记录实际考虑过的选项及取舍，不补造候选。
4. 用明确陈述写出决策、适用范围和时间；记录正负后果。
5. 写明实施/迁移影响、验证方式、风险、复审触发条件。
6. 状态变更保留历史；替代旧 ADR 时双向链接，不改写旧结论来隐藏演进。

使用[ADR 模板](references/template.md)。若决策尚未达成，状态保持“提议”，并列出待决问题。
