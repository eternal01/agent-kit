# 代码库导览

## 流程
1. 只读检查 README、项目规则、目录、构建与测试配置、入口和近期变更；先区分事实、推断和未知项。
2. 描述系统用途、运行/测试命令、主要模块、入口、依赖方向、数据或请求主路径，以及配置和部署边界。
3. 沿一条关键调用链追踪关键类型、状态变化和外部依赖；对证据不足的模块不臆测职责。
4. 标出高风险或高耦合区域、未覆盖的测试、明显的文档缺口和需要继续核验的点，但不扩展为代码审查或安全评估。
5. 按目标角色给出推荐阅读顺序和下一步；需要系统演进设计时转用 `system-architecture`，需要具体缺陷根因时转用 `systematic-debugging`。

按需使用[导览输出结构](references/output-template.md)。输出应包含文件路径和证据，不把目录名当作架构事实。
