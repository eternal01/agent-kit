# 编码规范治理

## 确认门禁
用户明确要求制定或落地规范，即视为对所述范围的授权。新门禁会阻塞现有构建、扩大修改范围或改变发布流程时，先说明存量影响并等待确认。

## 流程
1. 发现并优先遵循 README、AGENTS.md、CONTRIBUTING、语言配置及 CI 中的现有约定。
2. 只纳入与项目风险相关的规则；分别使用必须（MUST）、建议（SHOULD）、可选（MAY）。
3. 每条规则说明原因、正反例、适用范围和例外流程。
4. 能自动化的规则用格式化、lint、类型检查、测试或 CI 门禁执行，避免仅靠记忆。
5. 新门禁先评估存量影响，采用基线或分阶段收紧，不要求无关代码一次性整改。
6. 明确负责人、升级方式和定期复审条件。

按需参考[规范主题清单](references/checklist.md)。不复制语言官方规范；链接到它并只记录项目差异。
