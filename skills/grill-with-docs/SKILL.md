# 带留痕的对抗性澄清

## 流程
1. 读取仓库规则及已有 `CONTEXT.md`、`DECISIONS.md` 和 `docs/adr/`，复用现有约定。
2. 按 `grilling` 的设计树、动态提问和反例规则完成压力测试，不依赖链式技能调用。
3. 输出共同理解摘要和拟写入清单，区分事实、推断、决定和未决项。
4. 无论是否触发压力测试，都必须先展示方案和修改范围；未经用户明确确认，不得修改文件。出现新的重大疑问时暂停并重新确认。
5. 确认后按[持久化规则](references/persistence.md)写入术语、普通决策或 ADR。
6. 检查术语一致性、编号、交叉链接、未决项和 diff，再交给对应实施技能。

不替用户做业务决策，不把推断写成事实，也不把术语表当作规格说明。
