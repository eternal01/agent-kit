# 压力测试持久化规则

优先遵循仓库已有目录、模板、编号和状态约定。只记录用户已确认且需要跨会话或多人共享的信息，不记录草稿、推测、敏感信息和短期实现细节。

## `CONTEXT.md`

只记录项目术语及精确定义。每项包含术语、定义、适用边界和必要的同义词/禁用词；定义冲突时保留现状并先请用户裁决，不静默覆盖。

## `DECISIONS.md`

记录不满足 ADR 门槛但需要留痕的决定。每项至少包含日期、状态、范围、决定、依据、负责人和复审条件。变更旧决定时新增“替代”记录并链接原项，不改写历史。

## ADR

显著影响、难以逆转或需要长期解释的决策，先判断是否已达成，再按 `architecture-decision` 的边界、模板和仓库既有目录约定处理；此处不另设 ADR 模板或默认目录。

## 写入流程

1. 先列出拟新增、修改和替代的条目及目标文件。
2. 用户明确要求留档已确认内容，即授权在所述范围内写入；若决定未达成、变更既有结论、目的地不明或写入范围扩大，则展示拟变更并等待确认。
3. 最小化写入，使用稳定标识或链接关联术语、决策和 ADR。
4. 检查重复、冲突、断链、编号、未决项和 diff；证据不足的内容保持待确认，不写成结论。
