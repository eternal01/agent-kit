# 实施规划

## 前置条件
输入应包含已确认需求或设计。若关键决策缺失，列出阻塞项并停止，不在计划中暗自补设计。

## 流程
1. 阅读需求、设计、代码结构、测试/构建配置及项目约定。
2. 先列影响面：新增、修改、删除的文件及各自职责；保持现有边界，拒绝无关重构。
3. 按依赖顺序拆成可独立验证、可独立评审的交付任务，而非按技术层机械分组。
4. 每项任务写清文件、接口、前置依赖、具体步骤、验证命令、预期结果和回滚点。
5. 涉及兼容、数据或部署时，明确灰度顺序、迁移、监控、失败条件和回滚。
6. 高风险或存在重大歧义时，检查隐含决策、遗漏影响、失败条件和回滚路径；需要对抗性访谈时请用户明确提出。
7. 用户明确要求编写计划，即视为允许在所述范围内产出或写入计划；执行代码修改仍需单独授权。范围、迁移风险或关键决策变化时重新确认。
8. 对照需求逐条检查覆盖度、顺序、接口一致性及占位符；仅在该检查支持时声明计划完整，并列出未验证项。

按任务复杂度选用[实施计划模板](references/template.md)。计划描述“如何做”，不重复大段背景，也不强制逐步骤提交。
