# 实施计划模板

```markdown
# <主题>实施计划

## 目标与依据
- 需求/设计：<路径或链接>
- 完成条件：<可验证结果>

## 全局约束
## 代码实施路径比较（路径未定且存在实质取舍时）
| 可行路径 | 复用与改动文件/接口 | 迁移成本及依赖 | 验证与回滚 | 切换条件 |
|---|---|---|---|---|
| <一种可行路径；每种路径单独一行> | | | | |

在已确认验收条件内注明优化目标与推荐；关键取舍未经确认时只输出比较与待确认项，不展开任务。不可行的路径说明原因，不凑方案。
## 影响文件与职责
## 任务
### T1：<可独立验证的交付物>
- 文件：`path`
- 阻塞任务：<任务 ID 或无；说明依赖产物>
- 共享状态/并行限制：
- 接口变化：
- 步骤：
  1. 建立失败测试/基线证据。
  2. 完成最小实现。
  3. 更新必要配置、迁移或文档。
- 验证：`具体命令`
- 预期：<可观察结果>
- 回滚：<动作或不适用原因>

## 发布/迁移顺序
- 新旧版本与数据形态兼容矩阵：
- 扩展、兼容写入、回填、校验、切换、收缩及各阶段退出条件：
- 回填中断恢复、并发写入与数据一致性验证：
- 应用回退与数据恢复、不可逆点及演练状态：
- 无法独立通过验证的批次：集成分支、最终集成验证任务和发布限制。
## 风险与监控
## 需求覆盖检查
```

任务以交付物划分；省略不适用字段，不填写“待定”。
