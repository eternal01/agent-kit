# 响应角色与状态记录

仅在组织正在响应事故或进行事故演练时读取。优先沿用团队已批准的应急制度、严重级别、联系人和通报渠道；下列角色是职责分离建议，不要求小团队机械配齐，也不取代现有指挥体系。

## 职责

- **事件指挥**：维护整体态势、确定响应优先级、分派职责、管理决策与升级；不必亲自操作系统。
- **操作负责人**：协调获授权的技术缓解、恢复与验证；执行生产变更前核实范围和回退条件。
- **计划/记录**：维护时间线、行动项、依赖、证据和交接；记录失败尝试与状态变化。
- **沟通负责人**：准备内部/外部状态更新和更新时间；未经授权不发送，不替技术负责人推测根因或 ETA。

由一人承担多个职责时，明确说明兼任关系；出现冲突或负荷过高时，优先分离操作与指挥/沟通职责。

## 最小态势记录

```text
事故/演练：
状态与起始时间：
影响范围及证据：
负责人及职责：
已确认事实：
未知与待核实：
时间线（时间、行动/决策、责任人、结果/证据）：
当前缓解选项（影响、授权、验证信号、停止/回退条件）：
正在进行 / 阻塞的行动：
下一次评估或通报时间：
交接对象与确认：
恢复条件及残余风险：
```

只记录响应所需的信息；不得收集或输出密码、令牌、敏感个人信息或完整敏感日志。相关资料：[Google SRE《Managing Incidents》](https://sre.google/sre-book/managing-incidents/) 强调职责分离、事件状态文档、明确交接及事先演练；按本组织实际流程调整。
