# 学习笔记

## 边界

生成供个人理解、阅读和复习的内容。

- **快速知识点**：快速检索、恢复记忆和导航，不承担完整教学。
- **详细知识点**：围绕一个指定机制、数据结构、语言特性或设计模式，贯通使用、契约、表示、实现、原理、演进和取舍。
- **学习文章**：串联多个知识点，形成有前置知识、概念关系和练习的学习路径。

项目 README、API 文档和运维手册使用 `technical-documentation`；只核验时效事实使用 `web-research`；具体技术选型使用 `technology-selection`；正式架构决策使用 `architecture-decision`。

## 核心流程

1. 明确学习目标、已有基础、指定知识点、期望深度和阅读时间；信息足够时不追加形式化访谈。
2. 需要复用已有笔记且有获准访问的笔记来源时，先检索主题、来源日期、状态、置信度和关联对象；已有内容能承载新内容时优先更新，不创建同义副本。来源不可访问或用户只要求在聊天中整理给定资料时，直接注明未检索，不以知识库访问为前置条件。
3. 新资料优先核验规范、官方文档、源码、发行说明和设计提案。区分规范承诺、当前实现、历史事实、官方理由、综合推断和待确认内容。
4. 按[笔记形态](references/note-shapes.md)选择类型，不把快速知识点无限扩写，也不用摘要集合冒充详细知识点。
5. 生成详细知识点时读取[详细知识点规范](references/deep-dive.md)，由该文件统一定义内容链路、条件章节和完成检查；不把其完整结构套到快速知识点或来源摘要。
6. 实现说明必须落到真实数据结构、字段职责、调用路径、状态变化和资源成本，并明确稳定契约与版本实现的边界。关键结论附近放来源；无法核验的动机标记为“待确认”或“综合推断”，不得伪装成事实。
7. 使用可运行的最小示例、边界反例、流程图或实验；说明前置条件、预期现象、验证方式和结论边界，不虚构运行数据。
8. 按[知识整理方法](references/synthesis.md)去重、比较和关联。速查笔记链接详细知识点；详细知识点可链接实验、源码阅读、版本演进和 ADR。
9. 资料检索达到停止条件后仍缺证据时，明确记录未知，不用低质量来源填补。

## 保存笔记

默认在聊天中交付，不要求访问知识库。只有用户明确要求保存时才写入所述目的地；目的地不明先询问，更新前读取原文并保留个人批注。保存不默认授权创建属性、标签、关系或组织列表；扩大范围或处理敏感信息时重新确认。使用 Anytype 来源或保存到 Anytype 时，读取[Anytype 操作约束与属性映射](references/anytype.md)。
