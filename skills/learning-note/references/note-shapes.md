# 笔记形态

按用途选择一种主结构，不要求每篇笔记包含所有章节。

## 快速知识点

用于快速检索和恢复记忆，不承担完整教学：

```text
标题 → 一句话结论 → 关键事实 → 易错边界 → 详细知识点入口 → 来源
```

只保留稳定结论、关键词和导航；实现算法、历史演进和方案比较放入详细知识点。

## 详细知识点

用于围绕一个明确机制、数据结构、语言特性或设计模式建立完整知识体系。详细要求见[详细知识点规范](deep-dive.md)：

```text
使用与稳定契约 → 底层表示 → 关键操作与算法
→ 边界/复杂度/资源 → 原理与设计约束 → 设计动机
→ 版本演进 → 应用取舍 → 验证实验
```

必须区分实现者为什么这样设计，以及使用者在什么约束下采用或替换它。详细知识点不是项目 ADR。

## 学习文章

适合多个概念的系统学习：

```text
学习目标 → 前置知识 → 核心模型 → 概念之间的关系
→ 推导或示例 → 常见误解 → 练习 → 延伸阅读
```

学习文章可以引用多个详细知识点，但不应复制它们的全部正文。

## 来源笔记

适合文章、仓库、论文或讨论：

```text
来源信息 → 原文主张 → 我的理解 → 尚未核验 → 可应用场景
```

不要把原文摘要写成自己的结论。

## 对比笔记

适合方法或技术比较：

```text
问题和硬约束 → 比较维度 → 证据 → 适用条件 → 暂定结论 → 复审触发条件
```

## 个人反思

记录经历、理解变化和待验证判断。个人观点应以第一人称或明确标签呈现，不伪装成通用事实。
