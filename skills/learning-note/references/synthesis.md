# 知识整理方法

## 检索

1. 先用主题词、同义词和具体问题搜索已有笔记。
2. 只读取最相关的少量对象；摘要不足时再读取全文。
3. 记录笔记状态、来源日期和关联对象，避免把过期资料当作当前事实。

## 整理

- 已有笔记能承载新内容时更新原对象，不创建同义副本。
- 新内容改变旧结论时保留变化原因和日期，不静默改写历史。
- 一个笔记只维护一个主要问题；大型主题用对象关系连接，而不是无限加长正文。
- 快速知识点只保留结论、边界、关键词和入口；涉及底层结构、算法、版本演进或方案比较时，链接到对应详细知识点，不在速查中重复展开。
- 详细知识点应保持单一主要对象，但必须形成使用、契约、表示、操作、原理、演进和决策之间的因果链；不能只整理 API，也不能只翻译源码。
- 稳定规范、当前实现和历史实现分层表达。实现变化时保留旧结论的适用版本和变化原因，不用当前结论覆盖历史。
- 设计理由优先引用官方提案、设计文档、源码提交或维护者说明；只有实现证据时，将原因写成“综合推断”并注明置信度。
- 比较替代方案时使用相同维度：访问模式、复杂度、局部性、分配、并发、可靠性、可维护性与运维成本。避免只列优点或给出无约束结论。
- 速查笔记、详细知识点、实验/案例、源码阅读和 ADR 优先建立关系，不复制同一段正文。
- 来源列表保留标题、URL、版本或发布日期和访问日期；源码链接尽量绑定 Tag 或 Commit。
- 详细知识点的证据顺序通常为规范/标准 → 官方文档 → 官方源码与发行说明 → 官方提案/设计文档 → 维护者说明 → 社区资料。社区资料用于发现问题，不能覆盖更高等级证据。

## Anytype 最小属性

可使用现有 Page 类型，并按需要增加：

- `knowledge_kind`：quick-note、deep-dive、learning-guide、source-note、comparison、reflection
- `knowledge_status`：inbox、learning、evergreen、revisit、archived
- `topics`：主题标签
- `source_url`、`source_date`
- `review_after`
- `confidence`：high、medium、low
- `related_notes`：Objects 关系

属性是导航手段，不要求一次建齐。写入前先查询现有属性并复用等价字段；用户明确要求保存笔记时才创建或更新对象，创建新属性、标签或关系须另行确认，不因保存笔记而默认创建。逻辑类型与实际属性名不一致时，以知识库现状为准，并在结果中说明映射。

## 复习

优先选择到期、基础性强且能解除后续学习阻塞的内容。一次推荐 3～5 篇，并说明顺序依据；不要把整个知识库变成阅读清单。
