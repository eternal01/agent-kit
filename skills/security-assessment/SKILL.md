# 安全评估

## 流程

1. 确认评估对象、环境、数据敏感度、攻击者能力、非目标和可接受风险；未获授权不进行主动攻击或访问生产数据。
2. 建立资产、入口、信任边界、身份、权限、数据流和第三方依赖清单，证据不足处标为未知。
3. 按[威胁模型](references/threat-model.md)枚举滥用路径，优先检查跨边界操作、危险默认值、失败开放和供应链执行面。
4. 记录现有控制和可绕过条件。对高严重度候选主动寻找反证、前置条件和正常路径对照。
5. 按[评审清单](references/review-checklist.md)补查鉴权、输入、密钥、日志、依赖、隔离和恢复，不机械罗列不适用项目。
6. 使用[发现格式](references/finding-format.md)报告已证实问题、待确认风险和覆盖限制；风险等级必须对应可说明的影响与可利用条件。
7. 用户明确要求修复时再转入实施；扫描、安装工具、发送请求或修改系统前说明范围和副作用。

安全评估不是渗透测试或合规证明。没有证据时给验证方法，不把猜测写成漏洞。
