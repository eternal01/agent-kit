# 交接结构

按任务规模裁剪；省略不适用字段，未知项直接写“未知”及原因，不填写虚构值。

```markdown
# 任务交接

## 目标与范围
- 接手目标、完成条件、非目标：
- 已确认决策及来源：
- 待用户决定的问题：

## 当前工作区
- 目录、仓库、分支/提交、worktree 或 detached HEAD：
- 未提交与未跟踪文件、来源未确认的改动：
- 状态核验时间与方式：

## 进度与依据
- 已完成：产物路径及对应证据。
- 进行中：完成到哪一步。
- 阻塞/未验证：原因和解除条件。
- 最新检查：命令、工作目录、退出状态、结果与证据位置。
- 失败尝试：假设、动作、结果、是否已排除。

## 下一步
1. 核对当前工作区与本记录是否一致。
2. 按已确认计划处理下一项，列出验证与停止条件。
- 已有授权范围及来源（不替代接手会话权限检查）：
- 仍需确认的操作：

## 资料索引
- 规格、计划、ADR、issue、diff、日志或运行记录的位置。
- 敏感内容已省略；引用访问受控证据，不复制秘密。
```

路径应能由接手者定位；在不同机器间交接时使用仓库相对路径加提交标识，并说明未提交补丁的位置与可访问性。临时目录中的证据可能消失，应明确其生命周期，不能只留不可恢复的临时路径。

方法参考：[Matt Pocock handoff](https://github.com/mattpocock/skills/tree/main/skills/productivity/handoff)。此处默认聊天输出，不沿用自动写临时文件或调用特定 Skill 工具的行为。
