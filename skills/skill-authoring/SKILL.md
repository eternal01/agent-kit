# Skill 编写

## 确认门禁
用户明确要求创建或修改 Skill，即视为对所述范围的授权。触发边界不清、能力与现有 Skill 重叠、包含持久化或危险操作，或修改范围扩大时，先说明方案并等待确认。

会写文件或外部系统的 Skill 必须写清授权范围、暂停条件和持久化规则。

## 模式
编写与改进按以下流程；只读评审只报告发现，不执行写入步骤。盘点现有 Skills 时按[盘点方法](references/stocktake.md)输出保留、改进、更新、合并或退役建议。仅评测时直接按[行为对照评测](references/behavior-evaluation.md)准备与运行，不默认改写受测 Skill。

## 流程
1. 收集至少 3 个应触发和 3 个不应触发的具体请求，写入 `evals/triggers.json`，再确定单一职责与边界。
2. 检查现有技能；优先合并重复能力，避免同义名称和链式强制触发。
3. 使用小写连字符名称；`description` 用中文准确说明“做什么、何时用、不用于什么”。
4. `SKILL.md` 只保留边界、核心流程、关键约束和按需链接；每步写清可检查的完成条件，引用说明何种任务需要读取。详细知识放 `references/`，确定性操作放 `scripts/`，固定产物放 `assets/`。
5. 引用使用技能目录内相对路径；禁止依赖特定 Agent SDK，除非兼容性字段明确声明。
6. 按[评审清单](references/checklist.md)检查格式、渐进披露、触发冲突、可执行性和中文一致性。
7. 运行触发契约和静态验证。涉及触发、授权或关键流程变化时，按[行为对照评测](references/behavior-evaluation.md)准备基线、候选、开发/留出场景和证据记录；仅在获准的运行环境与预算内回放。未执行时明确标为待验证，不将静态通过当作行为改善。

避免写通用人格、常识和对所有任务生效的规则；这些内容会造成上下文污染。
