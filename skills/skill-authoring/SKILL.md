# Skill 编写

## 确认门禁
需求、触发边界或持久化行为存在重大歧义时，按 `grilling` 规则执行压力测试。无论是否触发压力测试，都必须先展示方案和修改范围；未经用户明确确认，不得创建或修改 Skill 文件。出现新的重大疑问时暂停并重新确认。

新建或修改会写文件的技能时，必须明确确认点、授权范围、暂停条件和持久化规则。

## 流程
1. 收集 3～5 个应触发和不应触发的具体请求，确定单一职责与边界。
2. 检查现有技能；优先合并重复能力，避免同义名称和链式强制触发。
3. 使用小写连字符名称；`description` 用中文准确说明“做什么、何时用、不用于什么”。
4. `SKILL.md` 只保留边界、核心流程、关键约束和按需链接；详细知识放 `references/`，确定性操作放 `scripts/`，固定产物放 `assets/`。
5. 引用使用技能目录内相对路径；禁止依赖特定 Agent SDK，除非兼容性字段明确声明。
6. 按[评审清单](references/checklist.md)检查格式、渐进披露、触发冲突、可执行性和中文一致性。
7. 用正反例模拟发现与执行；仅在用户允许时安装或运行脚本。

避免写通用人格、常识和对所有任务生效的规则；这些内容会造成上下文污染。
