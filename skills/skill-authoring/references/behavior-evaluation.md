# Skill 行为对照评测

## 何时运行

改变触发边界、授权规则或关键工作流时，优先做真实 Agent 对照。仅修正链接或措辞且不改变行为时可先做静态检查，并明确行为未回放。付费模型、依赖安装、外部写入和危险操作必须在用户允许的预算与权限内；缺少运行能力时交付场景和待验证项，不编造分数。

## 三层验证

| 层级 | 检查什么 | 不能证明什么 |
|---|---|---|
| 静态契约 | frontmatter、链接、正反例与冲突矩阵 | 实际路由准确率 |
| 触发回放 | 真实请求是否选择目标 Skill，是否误触发相邻 Skill | 任务一定完成 |
| 行为回放 | 任务产物、授权边界、证据与成本 | 未覆盖环境也可靠 |

描述优化应同时关注漏触发与误触发，不以扩大触发范围换取表面召回率。

## 对照流程

1. 从真实失败或高风险边界选任务，写清输入、前置环境、预期产物、禁止动作、独立判定条件。先冻结判据再运行，不根据候选输出修改评分规则。
2. 新 Skill 使用无 Skill 基线；已有 Skill 使用旧版完整目录快照。引用文件、工具脚本和全局发现列表也要固定，防止旧版间接读到新版。
3. 固定模型与版本、运行时、参数、输入快照、权限和预算。基线与候选使用独立会话和工作副本；不要把作者会话传给评测 Agent。
4. 触发测试只给请求和正常发现列表；执行测试才显式加载 Skill。无 Skill 基线不参与路由准确率计算，记为不适用并说明。
5. 保存工具轨迹、文件变更、外部副作用、验证输出及退出状态。逐项记录通过、失败、未运行与证据位置；Agent 自述成功不是证据。
6. 确定性检查优先自动化，语义评审使用冻结的量规与盲评，争议交人工。安全/授权违反不得由其他高分抵消。主观质量不强凑数字。
7. 关键场景至少做 3 组成对重复，记录耗时、token 和失败次数；无法测得的指标标为未知。分别报告触发、任务成功和越权情况，不用“多次中成功一次”冒充稳定性。
8. 用开发集迭代，用未参与调优的留出集检查回归；若据留出结果改写 Skill，补新留出样例。小样本只支持有限结论。

推荐覆盖只读请求、已确认小任务、错误审查意见、模糊前置条件、不可用工具和未经授权的持久化。对于约束型 Skill，加入时间压力或外部文本诱导场景，检查是否仍遵守授权边界。

## 改进与停止

从轨迹找具体失效点：误路由先修描述，遗漏资料先修引用条件，步骤跳过先明确完成条件。重复出现的确定性工作才考虑脚本化；不为单个案例堆例外。

新版没有稳定收益、成本明显上升或授权回归时保留旧版。运行成本到达约定上限即停止并报告未完成项，不自动加预算。原始记录保存在约定的受控位置，分享前脱敏，不默认进入 Git 或知识库。

## 方法来源

借鉴 [Anthropic skill-creator](https://github.com/anthropics/skills/tree/main/skills/skill-creator) 的基线对照与评测迭代、[Superpowers writing-skills](https://github.com/obra/superpowers/tree/main/skills/writing-skills) 的压力场景，以及 [ECC eval-harness](https://github.com/affaan-m/ECC/tree/main/skills/eval-harness) 的分层判定。此处为适配后的方法，不依赖它们的运行器或自动加载机制。
