# Skill 评审清单

## 触发契约

每个 Skill 保存 `evals/triggers.json`：

```json
{
  "positive": [
    { "request": "一个应触发的真实请求", "expected": "skill-name" }
  ],
  "negative": [
    { "request": "一个不应触发的相邻任务", "forbidden": ["skill-name"] }
  ]
}
```

正例和反例各至少 3 个。优先使用容易与相邻 Skill 混淆的请求，不用只含 Skill 名称的演示句。

## 触发
- 名称符合小写字母、数字和连字符规则，且与目录一致。
- 描述明确能力、触发条件和排除项；与其他技能无竞争。
- `evals/triggers.json` 至少保存 3 个正例和 3 个反例。
- 相邻技能包含交叉反例；静态契约通过后仍需按风险决定是否做真实 Agent 回放。触发回放应观察实际 `SKILL.md` 读取事件；不得以回答提及 Skill 名称代替触发证据。触发通过不代表任务产物正确或授权边界得到遵守。
- 行为变更还需按[行为对照评测](behavior-evaluation.md)检查任务产物与授权边界，准备旧版/无 Skill 基线、隔离会话、冻结判据及留出任务；报告失败、未运行项、授权与成本，不只报告最佳结果。

## 内容
- `SKILL.md` 简短，只含执行时必需信息。
- 详细资料按需放入 `references/`；`SKILL.md` 说明在什么条件下读取哪份资料，不建立多层链接迷宫。
- 流程可执行，无矛盾、占位符和特定会话假设；关键步骤有可检查的完成条件。
- 主文件只内联各分支共同需要的信息；分支专用资料的引用应说明读取条件。
- 脚本默认安全、参数化、可重复，安装或破坏性操作需用户同意。

## 可移植性
- 路径相对技能目录，文本为 UTF-8。
- 不依赖特定 Agent 的私有工具或目录；若必须依赖则声明兼容性。
- frontmatter 仅使用标准字段，`name` 与 `description` 必填。
- 面向用户和 Agent 的内容均使用中文（技术标识、命令和专名除外）。
- 新能力无法由现有 Skill 自然承载；若只是现有流程的一个模式，优先合并。
