# Skill 盘点

仅在用户要求盘点、评审或整合 Skills 时使用。默认只读输出，不安装、修改、删除或自动写缓存；执行合并、归档或退役前单独确认文件与影响。

## 流程

1. 明确扫描路径和范围，列出发现与未访问的目录。增量盘点只看自上次已知快照以来内容改变的 Skill；描述或边界改变时同时检查其相邻 Skills 和冲突用例。没有可信快照时不要声称已完成增量比较。
2. 阅读主文件及与判断有关的参考资料，对照项目规则、其他 Skills 和运行环境检查重复、失效引用、技术过时、授权边界及独特产物。
3. 如有获准读取的调用日志，可引用其时间窗口和样本量；没有日志时频率写“未知”。低频的安全、恢复或迁移能力不能仅凭频率退役。
4. 逐项给出下表结论；理由须有文件/段落或运行证据，不只写“过长”“重复”“未变”。
5. 汇总变更建议、依赖影响和需用户决定的项；跨 Skill 合并同时设计触发反例，避免任务失去入口。

| 结论 | 必要依据 |
|---|---|
| 保留 | 独特价值、当前适用场景与证据 |
| 改进 | 行为问题、目标章节、拟修改内容和验证方式 |
| 更新 | 过时版本/命令/事实及新的可信来源 |
| 合并到某 Skill | 明确目标、迁入内容、删除的重复内容与触发变化 |
| 退役 | 具体缺陷、替代能力、移除影响和恢复方式 |

输出至少包含 Skill、结论、证据、建议与影响。没有实际调用数据不得报告使用率；没有回放不得把文字更短等同于行为更好。用户要求保存盘点时再确认目的地并保留历史，不覆盖既有记录。

方法参考：[ECC skill-stocktake](https://github.com/affaan-m/ECC/tree/main/skills/skill-stocktake)。
