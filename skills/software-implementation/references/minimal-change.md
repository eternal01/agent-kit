# 最小充分变更

在已理解相关代码、调用链和验收条件后，按顺序检查；命中某层后停止，不为假想扩展继续向下设计：

1. **不改变**：现有行为是否已满足需求？
2. **删除或配置**：删除冲突逻辑、调整已有配置或开关能否完成？
3. **复用仓库能力**：是否已有组件、helper、模式或调用路径可复用？
4. **标准库或原生平台**：语言标准库、运行时或平台能力是否足够？
5. **复用已安装依赖**：现有依赖是否安全、维护良好且适合当前约束？
6. **局部修改**：能否在现有边界内完成最小实现？
7. **新增能力**：仅在前述路径均不足时新增依赖、抽象、模块、状态或公开接口。

## 不可裁剪项

不得为了缩短代码、省 token 或减少文件而删除：验收行为、信任边界校验、权限与安全控制、数据完整性与恢复、必要错误处理、兼容与迁移要求、可访问性，以及必要的可观测性和回滚能力。

## 需要说明的升级

当方案进入第 7 层，或新增生产依赖、公开接口、持久化状态、模块/服务，或修改多个不相邻子系统时，简要说明前一层为何不适用。无需为没有真实取舍的小改动生成仪式性说明。
