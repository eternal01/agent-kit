# 功能方案模板

```markdown
# <方案名称>
## 背景与问题
## 目标与非目标
## 用户/系统场景与验收标准
## 约束、假设与待确认项
## 最小路径检查（不改变、配置、复用、局部扩展）
## 功能行为比较与推荐（功能行为存在实质取舍时；不拆编码任务）
| 可行路径（最小改动／折中／长期，按需） | 场景与验收覆盖 | 体验、工期与改动成本 | 风险与验证 | 适用条件 |
|---|---|---|---|---|
| <一种可行路径；每种路径单独一行> | | | | |

以已确认的验收条件推荐当前可交付方案；尚未确认的新增功能只列待确认候选，不把折中路径写成本期承诺。说明必要的回滚与切换条件，以及暂留功能/体验债的影响和复审触发条件。不可行的路径写明原因，不凑齐三档，也不在此拆分编码任务。
## 职责、接口与数据流
## 异常处理与边界情况
## 测试策略
## 风险与后续工作
```

只保留与当前方案有关的章节。简单改动可在对话中使用同样结构，不创建文件。
