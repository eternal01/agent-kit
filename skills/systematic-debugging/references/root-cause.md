# 根因定位方法

## 反向追踪
从症状位置开始反复询问：
1. 哪个值、状态或事件直接造成失败？
2. 它由谁传入或改变？
3. 在上一层它是否已经异常？
4. 异常最早在哪个边界出现？

必要时在每个组件边界临时记录输入、输出、配置和关联 ID。日志应脱敏，并在调查结束后删除或转成适当级别的长期观测。

## 时序问题
用“等待可观察条件 + 明确超时”替代固定休眠。只有验证节流、超时等时间语义时才使用固定时间，并写明依据。

## 最小假设记录
```text
现象：
证据：
假设：因为 <证据>，<根因> 导致 <现象>。
实验：只改变/观察 <一个变量>。
结果：支持 | 否定 | 不确定
下一步：
```

验证失败就回到证据，不在原假设上叠加补丁。
