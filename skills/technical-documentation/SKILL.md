# 技术文档

## 确认门禁
用户明确要求创建或修改文档，即视为对所述范围的授权。事实冲突、目标受众不明、文档会改变既有承诺或修改范围扩大时，先说明问题并等待确认。

## 流程
1. 明确受众、使用场景、文档类型、维护者和完成标准。
2. 从代码、配置、接口定义、已确认设计和运行证据提取事实；冲突或缺失内容标为待确认。
3. 先建立面向任务的结构，再写正文；一个章节回答一个主要问题。
4. 示例必须最小、可复制并与正文一致；命令注明前置条件、风险和预期结果。
5. 按[技术文档风格](references/style.md)使用自然、直接的表达；删除聊天残留、假对比、空泛背景、重复总结和装饰性内容。
6. 检查链接、路径、版本、代码示例、frontmatter、术语、敏感信息及文档与实现的一致性。
7. 标注负责人、适用版本和更新触发条件（若项目有此约定）。

按文档类型选用[结构模板](references/templates.md)。设计内容未确定时先返回对应设计技能，不用流畅文字掩盖未知项。
