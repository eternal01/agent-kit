# 陌生读者测试

用于安装、API 接入、部署、恢复等需要读者独立执行的文档，或用户明确要求验证可理解性的任务。短小措辞和链接修正可省略，说明验证范围即可。

## 流程

1. 从受众目标选择 3–5 个实际任务，例如“从干净环境启动”“完成首次鉴权请求”“识别何时应停止回滚”。提前确定正确结果与权威事实来源，避免事后按回答放宽标准。
2. 给独立读者只提供文档及任务，不传原会话、作者推理、遗漏信息或标准答案。读者可以使用文档明确链接的公开材料；额外查阅到的资料应记录，不能掩盖缺失的文档入口。
3. 让读者给出答案/操作步骤、所需前置条件、歧义和无法完成之处。执行命令需要安全环境与授权；阅读测试不自动允许部署、生产访问、数据恢复或对外请求。
4. 作者将回答与代码、配置、接口定义和运行证据核对。逐项记录正确、误解、阻塞、未执行及证据，特别检查工作目录、环境变量、权限、版本、失败处理和恢复边界。
5. 修正文档中的缺口，对受影响任务重新使用独立上下文复测。存在关键阻塞时不得声明读者测试通过。

## 无独立读者时

没有独立会话、子 Agent 或人工读者时，交付问题清单和模拟走查结果，并明确“未执行独立读者测试”。作者自己知道背景的检查不能作为独立测试。

## 验收边界

读者能解释步骤不等于命令已实际运行；读者回答一致也不证明事实正确。报告必须区分事实核验、文档理解和实际执行三类证据。停止条件是选定任务中的关键前置条件、结果和风险均可从文档获得，且没有未解决阻塞；不能外推为所有读者和环境均可用。
