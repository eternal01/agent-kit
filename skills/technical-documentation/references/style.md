# 技术文档风格

## 写法

- 开头直接说明用途、适用范围或要解决的问题。
- 一个段落只承担一个主要信息；先写事实和动作，再补原因。
- 标题说明读者能在本节找到什么，不重复正文首句。
- 命令写明执行位置、前置条件、风险和可观察结果。
- 表格用于比较多项同类信息；两三句能说清时不用表格。
- 结论受证据约束。缺少名称、数字、日期或来源时，询问或标为未知。

## 删除

- “让我们深入了解”“值得注意的是”“综上所述”等聊天或过渡残留。
- 没有真实取舍的“不是 X，而是 Y”。
- 重复标题、前文或列表的章节结尾。
- 为追求整齐而使用的三段式、排比和碎片短句。
- “全面、强大、无缝、高质量、最佳”等没有证据的评价。
- 装饰性加粗、表情符号和口号。

## 修改现有文件

- 不改变代码块、命令、路径、环境变量、frontmatter、链接目标和技术标识，除非任务明确要求。
- 保留作者已有且不妨碍理解的语气差异，不把所有文件改成同一句式。
- 先修正事实、结构和重复，再处理措辞；不为“更自然”补造例子或观点。
