# Web 技术调研

## 流程
1. 把问题拆成可核验的主张，确定所需时效和证据标准。
2. 优先官方文档、标准、发行说明、安全公告和源码；社区内容用于发现线索，不覆盖一手来源。
3. 搜索限定产品、版本和日期；打开原文上下文，不根据摘要、搜索片段或转载下结论。对关键事实优先寻找独立来源；同一官方材料的镜像、转载或互相引用不算独立交叉验证。若单一官方原始来源已足以回答规范/产品承诺，说明该证据边界，不为凑来源扩大搜索。
4. 区分规范保证、当前实现、历史事实、厂商声明、第三方实测与推断；核对发布日期、适用版本、平台、地区及来源冲突。
5. 记录标题、URL、发布日期/更新时间和访问日期；结论附近附引用，并注明置信度、适用范围和仍待验证项。
6. 遇到搜索不可用、登录墙、动态页面、访问失败或结果互相矛盾时，说明具体限制；能用已知官方 URL 或源码继续核验时再尝试，不把失败检索伪装成无结果或已验证。
7. 达到问题所需证据标准后停止；有限的定向检索仍无法解决时，明确未知及下一项可验证证据，不无限扩展来源。

查询策略与证据等级见[调研准则](references/research-guide.md)。不得在命令、URL 或输出中泄露凭据。
