# 调研准则

## 来源优先级
1. 标准组织、厂商官方文档、发行说明、安全公告、许可证原文。
2. 官方源码、问题跟踪器和维护者声明。
3. 可信技术机构或作者的一手测量。
4. 社区问答、博客和聚合内容。

低优先级来源不能覆盖更高优先级的一手事实。涉及“当前、最新、支持、价格、安全”时必须核对发布日期和适用版本。先读官方原文及其适用范围；版本公告、规范条文和安全公告的结论以具体原始来源为锚点。补充交叉核验时，选择来源独立且覆盖同一主张的材料；同站转载、镜像、聚合摘要或相互引用不构成独立证据。单一权威原始来源已充分回答窄问题时，注明证据边界即可，不为满足数量而扩搜。

## 记录格式
```markdown
- 结论：<直接回答>
- 证据：[标题](URL)，发布/更新于 YYYY-MM-DD，访问于 YYYY-MM-DD
- 适用范围：<版本、平台、地区>
- 置信度：高 | 中 | 低
- 限制：<冲突或缺失>
```

引用应支持紧邻的结论；搜索结果摘要只用于定位原文。若搜索不可用或来源访问失败，记录查询/页面与失败范围；仅在问题确需时尝试已知原始 URL 或源码，不将“没搜到”表述成“不存在”。出现矛盾时先核对版本、日期、地区和规范/实现层次；仍无法解决则并列陈述并标为待确认。证据足够后停止；未解决的问题应具体说明缺哪类证据。
